## 0. 一页摘要

日报现在能回答"我做了什么"，不能回答"我读的东西从哪来、讲了什么"。本需求补两件事：

1. **R1 来源链接**：让页面级活动带上原始网址。做法是报告期反查浏览器历史库（Chrome / Edge），
   **默认关闭，由用户在设置页手动开启**；地址栏 OCR 作为兜底；禁止用标题猜 URL。
2. **R2 知识卡**：同一页面被多次截图时合并成一张卡，用本地抽取（L1）生成"这页在讲什么"，**只进日报附录**；设置里可选多一次模型调用（L2，默认关）。

同时覆盖微信/飞书内置浏览器与 PDF 阅读器：前者多半拿不到 URL，退到"域名级来源"或纯文本卡；后者用文件名解析成本地文件链接。

**分两批交付**：1.3.0 只做 R1 全线（含 R1 依赖的微信域名级、PDF 文件链接）；知识卡整块（R2）移到 1.3.1。
理由：R1 上线即可用且可独立验收；R2 的 L1 抽取质量必须拿真实数据看，先上 R1 才能拿到样本。

**图像型内容（原 D5）已定**：按方案 A 实现——不总结、只标注"未识别到文字"，不碰"图片永不出本机"这条硬约束。

## 1. 背景

What-IDid 的证据链是完整的：block_id 稳定、结论必须挂 block_ids、引用只能从 ref_id 清单里挑。但"引用"目前只覆盖**文档类**对象（本地文件、Obsidian 笔记、OCR 里出现的链接），**不覆盖"我今天读了哪个网页"**。

用户的实际诉求有两层：

- 想知道某条结论、某段阅读的**出处**（点得回去的原始网页）；
- 想知道**内容本身**（页面讲了什么），因为链接会失效，而"今天读了 40 分钟但什么都没留下"是常见状态。

两层诉求共用一个数据基础：**页面身份**（URL 或标题）与**页面文本**（OCR）。R1 解决身份，R2 解决内容。

## 2. 目标与非目标

### 2.1 目标

| 编号 | 目标 |
|---|---|
| G1 | 浏览器类活动块默认能拿到原始 URL（含 query），并渲染为可点链接 |
| G2 | 同一天同一页面只产出一张知识卡，卡片可回溯到 block_id 与截图 |
| G3 | 知识卡默认只出现在日报附录，正文不膨胀 |
| G4 | 无模型、断网、OCR 引擎缺失时仍能出卡（L1 本地抽取） |
| G5 | 微信/飞书内置浏览器、PDF 阅读器有明确的降级路径 |
| G6 | 新增数据可被 forget / retention 清理，分享版不泄漏 query |

### 2.2 非目标

- 不抓取网页正文（不联网、不带 cookie、不引反爬）。
- 不做"用标题搜 URL"或"按站点拼 URL"。
- 不把知识卡做成笔记系统（写 Obsidian 属于后续需求，见 §12 P4）。
- 不改 block_id 构成、不改 schema_version、不改模型"只能挑 ref_id"的约束。

### 5.2 历史库反查设计

**执行时机**：报告期（21:00 批处理），不在 20 秒采样里做。理由：采集期查库会放大 IO 与隐私面；历史库被浏览器独占，频繁读要反复拷贝；而报告是批处理，一次读一天最省事。

**数据源**：

| 浏览器 | 路径 | 表 |
|---|---|---|
| Chrome | %LOCALAPPDATA%\Google\Chrome\User Data\<Profile>\History | urls(id,url,title)、visits(id,url,visit_time,from_visit) |
| Edge | %LOCALAPPDATA%\Microsoft\Edge\User Data\<Profile>\History | 同上 |
| Firefox | %APPDATA%\Mozilla\Firefox\Profiles\<xxx>.default*\places.sqlite | moz_places、moz_historyvisits（**1.3.0 不实现**，仅记录以备扩展，§15 D-5） |

**读取方式**：把 History 与 -wal / -shm 拷到 state/tmp/，sqlite3 以 mode=ro 打开，读完即删。遇到加密、占用、企业策略禁读，记一条 debug 日志后跳过。

**时间换算**：Chrome/Edge 是"1601-01-01 起的微秒"，unix = visit_time/1e6 - 11644473600。

**匹配算法**（v0.1→v0.2：窗口从 ±30 秒改为向前回溯，见 §15 D-2）：

1. 对每个 block，取候选 visits，时间范围 **[start - lookback_sec, end + 30s]**，`lookback_sec` 默认 **3600**（60 分钟）。
   **为什么必须回溯**：History 只记「导航」，一篇读 30 分钟的文章只留开头一次访问，而块可能从任意时刻起头。
   实测（2026-11-05 真实数据，63 个浏览器块）：±30 秒窗只命中 40%、43% 连候选都没有；回溯 60 分钟命中 86%。
2. 标题相似度：窗口标题与 urls.title 归一化后（去空白、去站点后缀、小写）做 token 或字符序列重合率；
3. 打分：score = 0.6 * title_sim + 0.4 * (1 - gap/lookback)，其中 gap = max(0, block.start - visit_time)
   （访问发生在块开始之后的，gap 记 0；时间尺度统一用 lookback，不再用 90 秒窗）；
4. title_sim ≥ 0.8 且时间最近 → confidence high（0.95）；仅有时间命中 → medium（0.8，why 写明"时间命中，标题不一致"）；
   同一块多条按停留占比排序，最多 `max_urls_per_block` 条；
5. 结果按 block_id 聚合，**整份覆盖写** `urls.jsonl`（不 append）——报告期可能跑多次（21:00 起每 20 分钟 + 次日 04:05），
   覆盖写才能保证重跑结果一致、不叠加。

**注入方式**：构造 RefCandidate(raw=uri, kind_hint="url", block_ids=[...])，title_context 带页面标题，交给现有 RefResolver。**不新增 provider**——provider 链是给"解析器"用的，这里 URL 已经是终态，直接注入候选更简单，也不会打乱 refs.providers 配置语义。

### 5.3 域名级来源（内置浏览器）

微信内置浏览器（WeChat.exe / Weixin.exe）、飞书（Feishu.exe）多数情况**不写系统浏览器历史**（CEF 内核，独立 profile）。可行的降级：

- 微信文章页顶部通常有"网页由 mp.weixin.qq.com 提供"的小字，OCR 可捕获；
- 飞书内置浏览器部分版本显示地址栏，可走地址栏 OCR；
- 都拿不到时，**只记域名**：kind=url、uri=https://<domain>/、label=<domain>、why="仅识别到站点域名"、clickable=true、confidence low。

必须满足的约束：**域名必须来自 OCR 原文**，不能由标题推断。渲染时 chip 前加"仅域名"标记，避免读者误以为是原文链接。

### 5.4 本地文件来源（PDF）

PDF 阅读器标题通常就是文件名（规范_v2.pdf - Adobe Acrobat），normalize_title 后仍保留 .pdf。现有 RE_FILE 已包含 pdf，LocalFileProvider 会用 FileIndex 按文件名查绝对路径 → file:// 链接。

为此只需：refs.search_roots 配上文档目录（默认空，只认绝对路径）。**无需新代码**，属于配置与文档工作。

### 5.5 URL 归一化与脱敏（决策：保留 query）

用户决策：**存 query**。为兼顾隐私，采用"保留但打码"：

| 规则 | 处理 |
|---|---|
| fragment（#...） | 丢弃（#anchor 对来源无意义） |
| 敏感参数（token / access_token / sig / signature / password / pwd / key / secret / session / code / email） | 参数值替换为 [REDACTED]，参数名保留 |
| 追踪参数（utm_* / fbclid / gclid / spm / from） | **默认保留**（用户决策：存 query）；提供 url.strip_tracking: true 可关 |
| 超长参数值（> 64 字符且含大小写数字） | 打码（疑似 token） |
| 非 http(s) scheme | 丢弃（javascript:、file:// 分开处理） |
| 去重键 | 用 canonical = host + path + 排序后参数（去敏感值）；**ref_id 仍按原 uri 生成**，避免改动既有算法 |

分享版单独控制：share.keep_query: false（默认去 query），因为 export_safe.py 现在原样输出 uri。

## 6. R2 知识卡

### 6.1 粒度：页面会话（page session）

同一 (app, canonical_uri 或 normalized_title) 的连续块合并成一个会话：

- 优先用 URL 做键；无 URL 时用 app + 标题；
- 相邻块间隔 ≤ report.gap_threshold_min（默认 10 分钟）算同一会话；
- 停留时长 = 各块 active_seconds 之和；
- 文本 = 各块 OCR 行并集（不同滚动位置看到的内容互补）。

卡片数量上限：knowledge.max_pages（默认 10），按停留时长排序截断。

### 6.2 L1 本地抽取（确定性算法）

目标：不调模型，产出"这页在讲什么"的三行索引。**同样输入必须得到同样输出**（可重跑、可 diff）。

1. **收集**：会话内所有 OCR 行，保留首次出现顺序与出现次数。
2. **过滤**：
   - 长度 < 6 或 > 120 的行；
   - 纯符号行、纯 URL 行；
   - UI 词表（登录/注册/广告/推荐/分享/评论/更多/首页/上一页/下一页/搜索/下载 App）；
   - 站点模板行：在当天 ≥ 3 个页面的文本里都出现的行（导航、页脚、Cookie 提示）。
3. **打分**（每行）：
   - +2 与页面标题有词重合；
   - +1 长度在 10–60 字；
   - +1 含数字、冒号、等号、反引号、括号；
   - +1 在会话内出现 ≥ 2 次（跨滚动位置重复出现＝页面主体）；
   - -1 以"点击/登录/关注/立即"开头。
4. **产出**：
   - gist：标题 + 最高分行的前 40 字，截断到 60 字；
   - points：最高分的 3 行，各截断到 30 字；
   - quote：最高分且长度 20–80 的行，原样保留（用于校验"确实出现在屏幕上"）。
5. **置信度**：有 URL + 文本 ≥ 300 字 → high；无 URL 但有标题 + 文本 → medium；文本 < 100 字 → low。

### 6.3 Schema


**校验规则**（validate.py）：

- block_ids 必须真实存在，否则丢弃该卡并记 issue（与 highlights 同规则）；
- ref_id 不存在 → 记 issue 并降级为无链接卡；
- quote 必须是当日该会话 OCR 文本的子串，否则清空 quote（不删卡）；
- gist/points 中出现输入文本里没有的数字/版本号 → 丢弃该条。

### 6.4 渲染：只进附录（决策）

- **正文只出现一行统计**：「今日知识来源 5 条，合计 62 分钟（见附录）」，放在「时间分配」之后，不含任何卡片内容；
- **附录**新增折叠区「今日知识来源 · N」，每张卡：站点 + 标题 + 停留 + 3 条要点 + 原文引用 + 证据徽章（跳 block_id 锚点）；
- Markdown 归档：附录放在文末「证据与附录」节内，格式为三级标题 + 列表；
- 分享版默认**不含**知识卡（share.include_sources: false），因为这是内部阅读痕迹。

### 6.5 L2 可选模型摘要（默认关）

设置项 knowledge.model_summary: true 时，在报告主调用之后追加**一次独立调用**：

- 输入：最多 8 页 × 800 字的去重文本（不含图片）；
- 输出：sources[] 的 gist 与 points，quote 仍由本地从原文本挑选（防编造）；
- 失败/超时/无 Key → 静默回落到 L1，日报标 degraded；
- 成本：约为日报主调用的 +30%~50%，需在设置页写明。

### 6.6 证据口径

知识卡属于 **B 档（屏幕可见）**，措辞固定：

- 允许："页面显示……"、"屏幕上出现……"；
- 禁止："我读完了"、"我掌握了"、"已整理进知识库"；
- 卡片角标注明"来自屏幕 OCR，仅覆盖可见区域"；
- 纯标题卡（无 OCR 文本）只写标题，不写任何内容判断。

## 13. 风险

| 编号 | 风险 | 影响 | 缓解 |

### D5（**已定，2026-11-05**）图像型内容的"看图总结"

用户要求："无法 OCR 获得的，仅需要根据截图内容总结内容即可。"该要求与两条硬约束冲突：

| **A** | 不总结；卡片标"未识别到文字（图像型页面）"，保留截图缩略图与 block 锚点 | 0 | **已选定** |

| C | 用户显式开启"允许把该截图发给多模态模型"，逐次确认 + review_mode | 改隐私文档与硬约束 1，产品定位变化 | 否决（需签字才能翻案） |

## 附录 C：DECISIONS 条目草案

```markdown
## D-09 来源链接读浏览器历史库，但默认关闭

- 决定：报告期读取本机 Chrome/Edge 历史库，匹配活动块，URL 保留 query；**默认关闭**，
  由用户在设置页手动开启。
- 原因：历史库是本机只读数据，能给出精确 URL + 标题 + 访问时间，且可离线；
  地址栏 OCR 召回低、无行坐标，只能兜底；标题猜 URL 会造死链（否决）。
- 为何默认关：这是本项目第一次主动读取"与工作无关的本机隐私数据"（浏览历史）。
  默认开会让用户在不了解的情况下被读取，不符合"图片绝不出本机"这类保守默认的一贯立场。
- 代价：新装用户默认看不到来源链接，需要自己去设置页开；缓解为设置页显著提示 + 首次生成
  config.yaml 里的注释说明。
```
