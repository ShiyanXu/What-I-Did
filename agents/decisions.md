# 决策日志

> 记录「为什么这样做」以及「否决了什么」。改设计前先读，避免把有意为之的约束当成 bug 修掉。
> 新决策追加在末尾，格式：日期 / 决策 / 原因 / 否决方案 / 约束。

## D-01 零新增 pip 依赖（2026-10）
**决策**：只用标准库 + Pillow/numpy/requests/Jinja2/PyYAML/psutil。
**原因**：绿色版要能拷到任意 Windows 机器双击就跑；每多一个依赖就多一份 DLL 冲突与安装失败。
**否决**：mss（用 ImageGrab）、pywin32（用 ctypes）、apscheduler（用计划任务）、imagehash（手写 pHash）、
OpenAI SDK（一个 POST）、Flask（静态 HTML）。
**约束**：想要新能力时先找标准库/native API 的等价物；确实需要时在 `decisions.md` 记一笔再引入。

## D-02 图片永不出本机（2026-10）
**决策**：只把 OCR 后的文字发给模型，截图留在本地磁盘。
**原因**：屏幕内容包含聊天、文档、内部系统；发图等于把整屏隐私外传。
**否决**：视觉模型直读截图（效果更好，但隐私不可接受）。
**约束**：任何新增外发路径都必须经过 `privacy.redact_value()`；`check_privacy` 会拦。

## D-03 `block_id` 用时间 + 内容哈希（2026-10）
**决策**：`b-YYYYMMDD-HHMM-<hash4(app+title)>`。
**原因**：日报里每条结论要能回指到具体活动块，HTML 锚点与外部引用都依赖它；重跑同一天不能变。
**否决**：自增序号（重跑即变）、纯 UUID（不可读、无法从内容判断）。
**约束**：只增字段不改构成；`schema_version` 保持 1。

## D-04 时间由本地切，模型只填标签（2026-10）
**决策**：`behavior.py` 本地切 `seg-NN` 并给出起止时间，模型只填 verb/label/detail/confidence。
**原因**：模型对时间最不可靠，一旦把 09:12–10:07 写成 09:00–10:30，整条时间轴就废了。
**否决**：让模型自己分段（结果不可复现、跨天不一致）。
**约束**：渲染一律用本地时间；模型给的时间字段直接丢弃。

## D-05 模型只输出 JSON，排版在本地（2026-10）
**决策**：模型产出一个 JSON 对象，`templates/` 负责所有版式。
**原因**：版式要稳定、要能改、要能多语言；让模型写 Markdown 会每次长得不一样。
**否决**：模型直接写 Markdown 日报。
**约束**：模型不许写 URI，只能从 `ref_id` 清单里挑；`validate.py` 会核对真实性。

## D-06 出报与清理共用一把锁（2026-11-01）
**决策**：`WhatIDid.Report` 同时保护 `retention.clean` 与 `report.generate`，且支持等待重试。
**原因**：两者曾在 daemon 同一 30 秒轮次里相邻执行，导致一整天终版丢失。
**否决**：两把独立的锁（仍有交叉窗口）。
**约束**：`SingleInstance(wait=秒)`；daemon 主循环**先 `maybe_clean` 再 `_check_report_trigger`**。

## D-07 自动重试配额按「进展」计（2026-11）
**决策**：`tick.revision_of(day)` 涨了就归零；只有连续无产出才 5→10→20→40 分钟退避，上限 6 次。
**原因**：旧实现按次数计，21:00 起每 90 分钟一版增量正好吃满配额，04:00 补终版时一次 `busy` 就整天不再重试。
**否决**：固定间隔重试（费用不可控）、无限重试。
**约束**：`WHY_FINAL` 用完配额仍放行；`_check_report_trigger` 遍历 `due` 找第一个有配额的，不只盯最新天。

## D-08 日报判定改为「证据分档」（2026-11-05）
**决策**：`digest.SYSTEM_PROMPT` 把证据分 A/B/C 三档，只有 A 档（输入法候选框、相邻时点文字增量、
保存/提交/发送完成态、命令+回显）才能判「我做了」。聊天软件只认「已发出」。
**原因**：1104 的日报把「阅读 LLD」写成「把需求拆解写到 1.3.1.1」，把飞书群消息写成「我在讨论」。
根因是 prompt 只讲写作风格、不讲「屏幕能证明什么」。
**否决**：只在事后用规则过滤动词（治不了「把别人的消息当我参与」）；给每天加人工标注（成本太高）。
**约束**：判定过程不许写进正文（只进 `notes_for_human`）；块清单的「分类」不能当判定依据。

## D-09 文件名与本地化文案解耦（2026-11）
**决策**：文件名固定英文（`<day>.md`、`share/<day>-share.md`、`<day> daily report.md`），显示文案才翻译。
**原因**：文件名跟语言走会导致切一次语言多一份文件，`forget` 还会漏删。
**否决**：按当前语言生成文件名（旧数据无法统一）。
**约束**：旧命名 `-分享版.md` 由 `forget` 一并清理；JSON 不存显示文案（星期按日期重算）。

## D-10 禁止模块级 `t()`（2026-11-02）
**决策**：常量只存英文源，显示时调用 `t()`；默认参数改 `None` 再体内取。
**原因**：切语言是进程内重建窗口、不重新 import，模块级 `t()` 会永久冻在首次语言（v1.2.1 侧栏事故）。
**否决**：切语言时重启进程（会抢 `gui.lock`，新窗口一闪就退）。
**约束**：AST 体检要覆盖模块层、类体、函数默认参数；`t` 不能当局部变量名。

## D-11 `dev/` 不提交，`W:` 才是提交源（2026-10）
**决策**：`dev/` 只改和验，提交统一在 iMac 侧对 `W:\What-I-Did` 做。
**原因**：`W:` 共享对 Windows 侧**不能改名与删除**，而 git 提交要 write-temp + rename，所以在那边
提不了交；Windows 侧也没有 git 凭据。（早期把原因写成「不可写已有文件」，2026-11-06 实测可原地
覆盖；决策本身不变。）
**否决**：在 Windows 侧配凭据直接 push（用户明确不在 Windows 侧提权）。
**约束**：改动一律 `cp` 成 `.new`；`release/` 只由 `publish.py` 写；zip 不进 git。

## D-12 托盘自己调 `Shell_NotifyIcon`（2026-10）
**决策**：`tray.py` 用 ctypes 建隐藏窗口 + 消息循环。
**原因**：pystray/pywin32 都是新依赖，且 pystray 会把消息循环放在错误线程。
**否决**：pystray（依赖 + 线程模型不合）。
**约束**：托盘窗口必须独立线程 + 自己的 `GetMessage` 循环，跨线程只用 `queue`。

## D-13 zip 命名带版本号（2026-11-02）
**决策**：`What-IDid-win64-<版本>-<YYYYMMDD>.zip`。
**原因**：只带日期时同一天出补丁版会撞名，`make_zip` 会 unlink 旧包，发布页上两个资产分不清。
**否决**：只带日期（撞名）、带 commit 短哈希（每次构建都变，用户无法预期）。
**约束**：README 用通配描述指向 Releases 页，不写死文件名。

## D-14 读浏览历史默认关、只读当天、只存 URL（2026-11-05）
**决策**：`browse.history.enabled` 默认 `false`；开启后只把浏览器 `History` 拷进 `state/tmp` 只读查询，
只保留当天窗口内的访问，落 `data/<day>/urls.jsonl`，与当天数据同周期、`forget` 一并删。
**原因**：这是本项目第一次主动去读采集之外的本地数据，越界风险高于收益增量；由用户显式打开，
「图片永不出本机」（D-02）才不至于被顺手扩大成「顺手读点别的也行」。
**否决**：默认开（文档 v0.1 原写法，评审时推翻）；只存域名不存路径（丢掉链接就失去意义）。
**约束**：匹配必须向前回溯（`visits` 只记导航，±30 秒窗实测 40%，回溯 60 分钟 86%）；
块前只取最近一条，不把一小时前的无关页面挂上去；历史给不出时退到地址栏（需行坐标）再退到仅域名，
**永不猜路径**；`sqlite3` 必须进 `hiddenimports`，否则只有打包版会坏。

## D-15 Harness 复用单一事实源，先做单循环（2026-11-05）
**决策**：以 `AGENTS.md` + `PROGRESS.md` + `agents/decisions.md` 为既有入口、进度和决策事实源，新增
`feature_list.json` 管机器可读范围，`scripts/harness.py` 独占功能状态转移；trace 只写本机 `state/harness/`。
当前只实现可靠单循环与 `graph.md` 蓝图，不引入自动 loop、并行 agent、OpenTelemetry SDK 或图引擎。
**原因**：课程模板的 `claude-progress.md` / `CLAUDE.md` 与现有文件职责相同，再建一套会漂移；手工改
`passing` 又无法防止提前宣告完成。本项目多数改动是线性单功能流程，图化的协调与审阅成本大于收益。
**否决**：复制整套模板而不映射现有文件；agent 自行写通过状态；默认启用无限循环；为“可观测”新增
OTel 依赖；为了形式完整引入 LangGraph。
**约束**：WIP=1、依赖全通过才可启动、验证全成功才可 passing、passing 不可逆；失败保留在 trace 而不写成
通过证据。`blocked` 只能经 `resume` 恢复，且恢复要重过同一套 WIP 与依赖门控；`verification_commands`
一旦疑似含凭据（`sk-…`、`api_key=…`、Bearer token）静态校验直接拒绝——清单会提交，argv 还会进 trace。
trace 不含配置、密钥、截图或 OCR；本机仍不自动 commit/push/tag。只有 `graph.md` 的五项判据
至少三项真实出现时，才重新评估图化。

## D-16 自测脚本自己守住隔离边界（2026-11-05）
**决策**：`check_boundaries.py` 在未设置 `WID_HOME` 时直接返回 2，不再"提示一句然后照写"。
**原因**：它开头会删掉样本日的 `manual.json`，再写入合成补录与周汇总。文档写了"必须隔离"，但现场仍
留下过 `data/2026-10-18/manual.json` 和 `reports/weekly/2020-01-06_2020-01-12.md`——**文档约束挡不住的
事要交给脚本挡**，否则一次顺手裸跑就毁掉当天的人工补录。
**否决**：跑完自动清理（它删的正是真实文件，清理只能补救不能预防）；只在文档里加粗提醒（已经失败过一次）。
**约束**：E2E 与文档示例必须显式传 `WID_HOME`；要对着既有夹具目录跑，也必须显式设该变量。

## D-17 知识卡（R2）改落 1.4.0，而不是需求原定的 1.3.1（2026-11-06）· **已被 D-19 取代**
**决策**：`WID-REQ-2026-11-001` 的 R2（页面知识卡）目标版本改为 **1.4.0**；需求原文里「R2 移入 1.3.1」
作废。需求原文逐字归档在 `agents/requirements/wid-req-2026-11-001.md`，**不回改**；交付事实与当前口径
写在 `PROGRESS.md` 的「需求交付状态」一节，本条目只记「为什么改」。
**原因**：1.3.1 已经作为「审核按钮点不动」的补丁发出去（`60cc91e` / tag `v1.3.1`）。知识卡是新功能，
不是修复，占用已发布的补丁号会让人误以为 1.3.1 只是修 bug，也让同一版本号对应两份性质不同的产物。
版本语义在这里比「按原计划数字走」更重要。
**否决**：把知识卡塞进 1.3.1 的剩余额度（版本已发布，改不动）；发 1.3.2 装新功能（补丁号承载新功能，
同样破坏语义）；悄悄改需求文档里的版本号（原文是评审快照，改了丢失「当时为什么这么定」）。
**约束**：R2 开工前先补样本数据（`dev_fixture` 造含 `urls.jsonl`、微信文章块、PDF 块的一天），
否则 AC-13/14/15 没有判定依据；`share.include_sources` 在 R2 接线前一律按「预留未接线」表述，
不得在文档里写成已生效（见 `PROGRESS.md` 已知问题 10）。

## D-18 R2 拆成 R2a / R2b，R2b 暂缓（2026-11-06）· **已被 D-19 取代**
**决策**：R2 先交付 **R2a**（页面会话聚合 + 附录列表：站点 / 标题 / 停留 / 首行片段，不评分、不挑要点）；
**R2b**（L1 打分 + points/quote + L2 模型）暂缓，等攒够 3–5 天带 `lines` 的数据再评估。gist 一律严格取
原文片段（标题 + 首行前 40 字），不做概括——概括会越过 D-08 的 B 档措辞。
**原因**：拿 2026-11-05 真实数据按需求 §6.2 跑原型，卡片不可用：行级抽取产出残句（`…fo:×`、
`…并给了它一句话定义：`），因为屏幕行是按视觉宽度切的；`(app, 标题)` 把全天飞书聊天并成两张相同的卡，
内容还全是别人的消息；前 40 个会话最高分只有 2–4 分，界面控件与正文同分；`other`/`meet` 块未过滤，
会产出「会议知识卡」。而且 `lines` 行坐标只有 v1.3.0 之后采集的日期才有，现在没有可评估的数据。
**否决**：按 §6.2 原样实现 L1（不可用且无法验收）；用模型生成要点替代 L1（改动证据口径，等于放松 D-08）；
先用合成样本评估（合成数据看不出断行与界面噪音）。
**约束**：R2a 只对 `web` / `doc` 类生成；聚类键优先 URL，无 URL 时用 `(app, 标题)` 但标题等于应用名
（如「飞书」「微信」）时直接丢弃；卡片措辞固定「页面显示……」，禁止「我读完了 / 已整理进知识库」；
分享版默认不含知识卡；`share.include_sources` 在 R2 接线前保持「预留未接线」的表述。

## D-19 定位收窄到「记录工作」：知识卡（R2）与来源链接（R1）都移出范围（2026-11-06）
**决策**：软件只回答一个问题——**我这一天做了什么**。据此：
- **R2 知识卡整块取消**，含 D-18 拆出的 R2a（会话聚合 + 附录列表）与 R2b（L1 打分 + L2 模型）。取代 D-17 / D-18。
- **R1 来源链接也从产品里移除**：读浏览器历史、地址栏 OCR 兜底、仅域名兜底、日报里的可点链接、
  设置页「读历史 / 地址栏」两个开关、`doctor` 的 `Source links` 检查项。**回退已在 `1.4.0` 执行完毕**
  （用户先定「暂不发版、攒反馈」，随后改为直接裁剪并重新发版），逐文件实况见 `PROGRESS.md` 的
  「R1 移除实况」——那里也记了最初清单漏掉的四处消费者。
**原因**：知识库类功能让软件冗余、不纯粹。知识内容的总结与跳转（这页讲什么、点回原文）属于外部工具
（Obsidian、浏览器历史）的职责，塞进采集器会让它从「工作记录」变成半个笔记软件；R1 产出的链接唯一用途
就是跳回页面，正是被否掉的那一类。定位越窄，越容易做对一件事。
**否决**：只砍 R2、保留 R1（R1 的存在理由就是跳转，留着等于留着半个已否掉的东西）；
保留 R1 但去掉 href 只显示域名（半成品，维护成本不降，还留着历史库读取与一块隐私面）；
砍功能但保留配置键（能配不生效，正是已知问题 10 那种冗余）。
**约束**：
- **已发布的 v1.3.0 / v1.3.1 不回滚**：资产、tag、Release 一律不动，移除只发生在下一个版本。在此之前
  文档不得写成「已移除」——功能仍在、默认关闭。
- 新功能准入判据：**它是在记录「我做了什么」，还是在管理「这些内容是什么」？** 后者不进这个软件。
- R1 移除时 `url.*` 配置与 `privacy.normalize_url/canonical_url` **必须保留**：`export_safe.py`（分享脱敏）
  与 `refs/resolve.py`（引用归一化）都在用，它们不属于来源链接。
- `ocr.jsonl` 的 `lines` 字段是否随 R1 一起删，移除时再评估（保留=不动数据格式；删除=每块少一份行坐标）。
